Настройка сети au-team.irpo

Пошаговое руководство по всем машинам: провайдер, маршрутизаторы, коммутатор, сервер, рабочие станции и межсетевой экран филиала. Нажмите на устройство на схеме, чтобы перейти к его настройке.

Пунктир — GRE-туннель между главным офисом и филиалом.

ISP

Машина провайдера

Имя машины

hostname

Показывает текущее имя машины в сети. Сейчас у неё стандартное сгенерированное имя reuug4wfsudlu.

hostnamectl set-hostname isp.au-team.irpo

hostnamectl навсегда меняет имя на то, что требует задание. При повторном вызове hostname система подтвердит изменение.

Интерфейсы: настройка не требуется

ip a

Команда выводит все сетевые интерфейсы и их адреса:

  • ens3 смотрит во внешнюю сеть провайдера и получает адрес по DHCP (10.0.137.220).
  • ens4 и ens5 имеют статические адреса 172.16.1.1 и 172.16.2.1 для связи с маршрутизаторами главного офиса (HQ) и филиала (BR).

Все адреса уже на месте.

Пересылка пакетов: настройка не требуется

vim /etc/net/sysctl.conf

В конфигурационном файле ядра есть строка net.ipv4.ip_forward = 1. Она включает режим маршрутизатора: Linux пересылает пакеты между интерфейсами.

NAT (маскарадинг)

iptables -t nat -L

Выводит таблицу nat. Цепочки пустые, поэтому интернет на внутренние машины пока не раздаётся.

iptables -t nat -A POSTROUTING -o ens3 -j MASQUERADE
iptables-save >> /etc/sysconfig/iptables
systemctl enable --now iptables
  1. Первая команда заставляет ISP подменять адрес всех пакетов, идущих из внутренних сетей в интернет, на адрес внешнего интерфейса ens3.
  2. Вторая сохраняет правило в файл, чтобы оно не пропало после перезагрузки.
  3. Третья добавляет службу iptables в автозагрузку и сразу запускает её.

Часовой пояс: изменения не нужны

timedatectl

Установлен Europe/Moscow (MSK, +0300).

HQ-RTR

Маршрутизатор главного офиса (EcoRouter)

Имя устройства

ecorouter>en
ecorouter#sh hostname

en (enable) переводит маршрутизатор в привилегированный режим. sh hostname показывает стандартное имя ecorouter.

en
conf t
hostname HQ-RTR
ip domain-name au-team.irpo
end
write memory

Заходим в режим конфигурации (conf t), меняем имя на HQ-RTR и задаём доменную зону организации. end возвращает назад, а write memory (или wr) сохраняет конфигурацию в энергонезависимую память.

IP-адреса: настройка не требуется

sh ip interface brief

Выводит краткую таблицу интерфейсов с адресами и статусом (up включён, down выключен). Видны настроенные VLAN (vl100, vl200, vl999) и стык с провайдером (isp).

Пользователи: настройка не требуется

sh users localdb

Показывает учётные записи, созданные на самом роутере. Администратор net_admin с правами admin уже есть.

GRE-туннель к филиалу

sh interface tunnel.0

Если команда ничего не возвращает, туннельного интерфейса ещё нет.

en
conf t
interface tunnel.0
ip address 10.10.10.1/30
ip tunnel 172.16.1.2 172.16.2.2 mode gre
end
write memory

Создаётся виртуальный туннель tunnel.0 с внутренним адресом 10.10.10.1. Командой ip tunnel он привязывается к реальным адресам: наш внешний (172.16.1.2) и адрес роутера филиала (172.16.2.2). Режим инкапсуляции — GRE.

Маршрут по умолчанию

sh ip route

Роутер знает только сети, к которым подключен напрямую (буква C, Connected). Строка Gateway of last resort is not set означает, что он не знает, куда отправлять пакеты в интернет.

conf t
ip route 0.0.0.0 0.0.0.0 172.16.1.1
end
write memory

Команда говорит: если адрес назначения неизвестен, отправляй пакет провайдеру (172.16.1.1). В таблице появится запись S*, статический маршрут по умолчанию.

OSPF между HQ и BR

en
conf t
router ospf 0
network 10.10.100.0/27 area 0
network 10.10.200.0/28 area 0
network 10.10.30.0/29 area 0
network 10.10.10.0/30 area 0
passive-interface default
no passive-interface tunnel.0
area 0 authentication
exit
interface tunnel.0
ip ospf authentication message-digest
ip ospf message-digest-key 1 md5 P@ssw0rd
end
write memory
  1. router ospf 0 запускает процесс динамической маршрутизации.
  2. Команды network … area 0 объявляют локальные подсети и сеть туннеля в зоне 0, чтобы роутер филиала узнал о них.
  3. passive-interface default отключает служебные OSPF-пакеты во всех пользовательских сетях (безопасность и экономия трафика).
  4. no passive-interface tunnel.0 разрешает OSPF работать через GRE-туннель.
  5. Остальные команды включают аутентификацию MD5 с паролем P@ssw0rd на туннеле, чтобы посторонние не могли подбросить ложные маршруты.

NAT для локальной сети

en
conf t
interface isp
ip nat outside
exit
interface vl100   ! то же для vl200 и vl999
ip nat inside
exit
ip nat pool HQ 10.10.0.1-10.10.200.254
ip nat source dynamic inside-to-outside pool HQ overload interface isp
end
write memory
  1. Роутеру указывают, где внешняя сеть (ip nat outside на интерфейсе к провайдеру) и где внутренние (ip nat inside на интерфейсах VLAN).
  2. Создаётся пул адресов и включается динамический NAT с перегрузкой (overload), чтобы все компьютеры из внутренних VLAN выходили в интернет через один внешний адрес интерфейса isp.

Часовой пояс

conf t
ntp timezone utc+3

Настраивает московское время (+3 часа к UTC).

BR-RTR

Маршрутизатор филиала

Зеркало HQ-RTR

Все шаги полностью повторяют настройку HQ-RTR, только с адресами филиала.

  1. Доменное имя меняется на BR-RTR.
  2. GRE-туннель настраивается встречно: адрес в туннеле 10.10.10.2, адрес назначения 172.16.1.2 (роутер HQ).
  3. Маршрут по умолчанию указывает на шлюз провайдера для филиала: 
    ip route 0.0.0.0 0.0.0.0 172.16.2.1
  4. OSPF запускается так же, а в network добавляются подсети филиала. Что роутеры увидели друг друга через туннель, проверяем командой: 
    sh ip ospf neighbor
    В выводе должно быть состояние Full.

HQ-SW

Коммутатор главного офиса (Linux + Open vSwitch)

Имя

hostnamectl set-hostname hq-sw.au-team.irpo

VLAN: настройка не требуется

ovs-vsctl show

Выводит схему виртуального коммутатора OVS. Порты уже распределены по VLAN:

  • ens4 во VLAN 100 (сеть серверов).
  • ens5 во VLAN 200 (сеть пользователей).
  • ens3 работает как trunk-порт: пропускает тегированные пакеты 100, 200 и 999 до роутера HQ-RTR.

Всё работает корректно.

HQ-SRV

Сервер главного офиса (ALT Linux)

Статический IP через etcnet

Графического интерфейса нет, поэтому сеть настраивается файлами в /etc/net/ifaces/ens3/.

  1. options: задаём BOOTPROTO=static. Адрес берётся не из DHCP, а настраивается вручную.
  2. ipv4address: вносим 10.10.100.2/27, постоянный адрес сервера в сети серверов.
  3. ipv4route: прописываем default via 10.10.100.1. Пакеты во внешние сети уходят на роутер HQ-RTR.
  4. resolv.conf: прописываем search au-team.irpo и внешние и внутренние DNS-серверы.
systemctl restart network

Сетевая служба перезапускается и читает новые данные. Проверить результат можно командой ip a.

Права администратора (sudo)

Группа администраторов wheel пока ограничена.

vim +123 /etc/sudoers

Раскомментируйте строку WHEEL_USERS ALL=(ALL:ALL) NOPASSWD: ALL. Тогда пользователи группы wheel (например, sshuser) смогут выполнять любые команды через sudo без ввода пароля.

Безопасность SSH

По заданию нужно ограничить попытки входа и показывать приветственный баннер при подключении.

  1. В /etc/openssh/sshd_config раскомментируйте строку Banner /etc/openssh/banner. Служба SSH будет читать текст из этого файла.
  2. В файл /etc/openssh/banner запишите: Authorized access only. (доступ только для авторизованных лиц).
  3. Перезапустите службу: 
    systemctl restart sshd

DNS-сервер (BIND9)

Сервер преобразует доменные имена в IP-адреса внутри корпоративной сети.

  1. options.conf: строка listen-on { 10.10.100.2; }; заставляет сервер слушать запросы на своём адресе. Строка forwarders { 77.88.8.8; }; перенаправляет неизвестные имена (например, google.com) на публичный DNS Яндекса.
  2. Файлы зон (au-team.irpo.zone и 10.10.in-addr.arpa): исправляются ошибки в SOA-записях, адрес почты администратора по умолчанию заменяется на root.au-team.irpo.. В файлах жёстко прописаны соответствия имён, например hq-rtr IN A 172.16.1.2.
  3. Запуск: 
    systemctl enable --now bind.service
    Команда запускает DNS-сервер и добавляет его в автозагрузку.

HQ-CLI и BR-CLI

Рабочие станции пользователей

HQ-CLI

Машина получила сетевые настройки по DHCP от роутера: 10.10.200.2/28 с пометкой dynamic. Имя хоста задаётся через hostnamectl.

BR-CLI

Автоматическая настройка сети не сработала: интерфейс ens3 пустой. Что делает администратор:

  1. Переходит в режим суперпользователя (su -).
  2. Переименовывает ошибочную папку интерфейса ens18 в ens3.
  3. Вручную прописывает статический IP 10.20.30.2/29 и шлюз филиала 10.20.30.1, по аналогии с сервером.

BR-FW

Межсетевой экран филиала (Ideco UTM)

Настройка через веб-интерфейс

Ideco UTM настраивается удалённо через браузер с рабочей станции филиала BR-CLI.

  1. Откройте браузер и введите внутренний адрес шлюза: 10.20.30.1:8443. Войдите под учётными данными по умолчанию.
  2. В веб-панели смените имя устройства на br-fw.au-team.irpo.
  3. Настройте OSPF, чтобы шлюз автоматически обменивался маршрутами с роутером филиала.
